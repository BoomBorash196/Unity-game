# Скины: как добавить свою модель

Сейчас в игре **21 скин**: 7 процедурных (собраны из примитивов в коде),
2 импортированных FBX и 12 наград дейликов/батл-пасса.

## Способ 1: бросить FBX и забыть (30 секунд)

1. Скинь свой **FBX** в папку `Assets/Resources/Skins/`.
2. В инспекторе на корне модели добавь компонент **`SkinMarker`**.
3. Заполни `Skin Id` (латиницей, без пробелов) и `Title`.
4. Модель автоматически появится в меню → «Скины» и в игре.

Без `SkinMarker` модель тоже появится — просто с дефолтными условиями
(рекорд 100 м, имя = имя файла).

`Id` должен совпадать с именем файла в нижнем регистре, иначе будет дубль:
код объявленный вручную всегда побеждает автонайденный.

## Способ 2: объявить в коде (если нужны текстуры)

`SkinMarker` не умеет назначать текстуры — их надо положить в
`Assets/Resources/Skins/Textures/` и прописать в коде. Поэтому оба FBX-скина
объявлены в `Assets/Scripts/Core/SkinCatalog.cs` (методы `Willow()` и
`Wingsage()`). Копируешь метод — получаешь свой скин.

```csharp
private static SkinDefinition MyHero()
{
    var skin = new SkinDefinition
    {
        Id = "my_hero",                       // = имя файла в Resources/Skins
        Title = "Мой герой",
        Description = "Со скелетом, полная анимация",
        ResourcePath = SkinCatalog.ResourceFolder + "/my_hero",
        ModelYaw = 0f,                        // если модель смотрит не в +Z
        ModelScale = 1f,                      // 1 ≈ 1.9 м, правится одним числом
        TintImported = false,                 // покрасить цветом BodyColor
        Unlock = SkinUnlock.Coins,
        UnlockValue = 900
    };

    // Ключ — часть имени материала/сабмеша. Нормали сравниваются по longest match.
    skin.Textures["armor"] = new SkinTexture
    {
        Diffuse = SkinCatalog.TextureFolder + "my_hero_armor_color",
        Normal  = SkinCatalog.TextureFolder + "my_hero_armor_normal"
    };

    return skin;
}
```

Не забудь вписать вызов в список в `SkinCatalog` (рядом с `Willow()`).

## Что настраивается в `SkinMarker`

| Поле | Смысл |
|---|---|
| `Skin Id` | уникальный ключ, по нему сохраняется покупка |
| `Title` / `Description` | подпись в меню |
| `BodyColor` / `AccentColor` / `TrimColor` | цвета превью; `BodyColor` же красит модель, если на ней нет текстур |
| `Tint` | красить модель целиком в `BodyColor` (если у модели есть текстуры — выключи) |
| `ModelYaw` | поворот, если в FBX модель смотрит не в **+Z** (0/90/180/270) |
| `ModelScale` | итоговый рост модели, 1 ≈ 1.9 м |
| `Unlock` | `Free` / `Height` (рекорд, м) / `Checkpoint` / `Coins` / `Points` |
| `UnlockValue` | рекорд в метрах или номер чекпоинта (зависит от `Unlock`) |
| `CoinCost` / `PointCost` | цена, если `Unlock` = `Coins` / `Points` |

Рост и позиционирование делает `SkinApplier` сам: модель любого масштаба
подгоняется под `CharacterController` (рост 1.9 м, ступни на земле, центр по
оси капсулы). Коллайдеры, камеры, свет, аудио и анимация из FBX вырезаются
автоматически.

## Настройки импорта FBX

Для скинов с анимацией кодом в FBX ничего анимировать не нужно, поэтому
`Model Importer` ставится так:

| Вкладка | Параметр | Значение | Зачем |
|---|---|---|---|
| Rig | `Animation Type` | `Generic` | нужен скелет; с `None` Unity разбирает модель на статичные меши |
| Model | `Import Animation` | off | клипов нет, Animator не нужен |
| Model | `Read/Write Enabled` | on | `SkinApplier` считает точные габариты по вершинам |
| Model | `Import Cameras` / `Import Lights` | off | мусор из сцены |
| Model | `Import Materials` | `Standard` | совпадает с `Palette.Textured` |
| Model | `Preserve Hierarchy` | on | иначе Unity склеит `SkinnedMeshRenderer` c `Animator` |
| Texture | `Normal Map` / linear sRGB | для `*_normal` | иначе карта нормалей мылится |
| Texture | `Max Size` | 1024 | мобильный бюджет |

Риг, гашение клипов и чтение мешей теперь ставит код: `Assets/Editor/ModelImport.cs`
на импорте включает `Animation Type = Generic`, выключает импорт клипов и включает
`Read/Write` у всего, что лежит в `Assets/Resources/Skins/`. У моделей Dota в FBX
~256 клипов, игра их не использует (движение процедурное), а весят они больше самой
модельки — и FBX лежит в `Resources`, то есть попал бы в сборку целиком.

**Важно:** `Animation Type = None` **не годится** — Unity тогда не строит скелет и
раскладывает модель на статичные `MeshRenderer`. Кости на месте, но ничего к ним
не привязано, и анимация не двигает меши. Нужен именно `Generic` + выключенные
клипы.

**Важно:** `Read/Write Enabled` нужен, потому что `SkinApplier` меряет габариты
модели по вершинам (bind-pose меш не отражает позу: крюк, пересаженный костью в
руку, мерился бы у ног). В редакторе вершины читаются даже без флага — сборка
падает с `Not allowed to access vertices`; это ловится проверкой `rig.readable`.

Остальные строки таблицы уже прописаны в `.meta` всех FBX — руками делать не
нужно, если меняешь скин, повтори для нового.

## Ориентация: как понять, куда смотрит модель

Направление **не угадывается**, а меряется. Удобный способ — открыть в
инспекторе скелет и посмотреть, куда смотрят кости лица/кистей рук, или
вывести в лог средний вектор от бёдер к ступням. Все три образца уже
проверены численно:

| Скин | Куда смотрит | `ModelYaw` |
|---|---|---|
| `classic` (контрольный) | +Z | 0 |
| `dark_willow` | −Z | **180** |
| `lowpolymage` (без скелета) | +Z | 0 |

Если модель без костей, ориентацию меряют «столбиками» — усреднённым
центром вершин, разбитых по Y. Модель смотрит туда, куда смещается центр
вершин верхних столбиков относительно нижних.

## Анимация

Анимаций в FBX нет и не нужно — `SkinAnimator` крутит кости процедурно:

- бег — фаза идёт от пройденного расстояния, ноги не скользят;
- прыжок/падение — поджатые ноги, руки вверх, наклон корпуса;
- приземление — squash & stretch по силе удара;
- wall slide — наклон к стене по её нормали;
- **без костей** — парение, покачивание и взмахи «крыльями» всей моделью;
- **без костей, с отдельными мешами** — части двигаются друг относительно друга.

### Анимация модели без костей

Если в модели нет скелета, аниматор работает с целыми мешами: находит крылья,
голову и корпус и двигает их относительно друг друга. Конечностей у такой
модели нет, и анимировать нечего — на маге с крыльями работают именно части.

Части определяются **по форме габаритов, а не по именам**: в импортированных
FBX имена обычно «Cube», «Cube.001» и ничего не говорят о назначении.

| Часть | Как отбирается |
|---|---|
| Крылья | Самая широкая часть, и она заметно (в 1,5 раза) шире второй по ширине |
| Корпус | Самая высокая из оставшихся |
| Голова | Наивысшая вершина среди оставшихся, если она ниже корпуса хотя бы на четверть |

Габариты считаются в системе координат самой модели, а не в локальной системе
части. У импортированных мешей произвольный локальный масштаб, и по собственным
размерам корпус выходит меньше головы — классификатор путает их местами, и
тогда корпус остаётся неподвижным, а вместо него двигается голова.

Прыжок должен читаться сильнее бега. В воздухе скорость бега падает, и вклад
фазы бега в амплитуду исчезает вместе с ней, поэтому вклад воздуха заведомо
больше: иначе в прыжке крылья бьют слабее, чем на бегу.

### Как находятся кости

Имя кости нормализуется: отрезается префикс экспорта (`mixamorig:`,
`Armature|`, `DEF-`, `B-`, `Bip01`/`Bip001`), убираются `_ - . | пробелы`,
приводится к нижнему регистру, а числа схлопываются (`spine.001` → `spine1`,
чтобы бонусные кости не терялись). Дальше идёт поиск по списку синонимов:

| Что ищем | Синонимы (примеры) |
|---|---|
| Таз | `Hips`, `Hip`, `Root`, `Pelvis`, `Armature` |
| Грудь | `Chest`, `UpperChest`, `Ribcage`, `Torso` |
| Голова | `Head`, `HeadTop` |
| Плечо | `LeftArm`, `LeftUpperArm`, `UpperArm.L`, `UpArm.L`, `LArm` |
| Предплечье | `LeftForeArm`, `ForeArm.L`, `LowerArm.L` |
| Бедро | `LeftUpLeg`, `LeftThigh`, `Thigh.L`, `UpLeg.L` |
| Голень | `LeftLeg`, `LeftShin`, `Shin.L`, `Calf.L` |

Покрыты Unity Humanoid, Mixamo, Blender и 3ds Max. Пропущенное достраивается
по структуре: таз — общий предок обеих ног, грудь — «дедушка» плеча, позвоночник
— родитель груди. Скелет, у которого корневая кость буквально называется
`Spine`, читается как таз.

**Проверить, что скелет распознался:** в лог можно вывести `BoneReport()` —
он печатает, какая кость на что подобралась (`hips=… shinL=…`). У Тёмной Ивы —
единственного импортированного скина со скелетом — нашлись все 12 костей.

**Если в костях нестандартные имена** (так у ригов Source/Dota: `spine1`,
`bicep_L`, `thigh_R`): не переименовывай кости, а задай карту ролей в скине —
`skin.BoneNames["hips"] = "spine1"` и т.д. (12 ролей: `hips`, `spine`, `chest`,
`head`, `armL`, `foreL`, `armR`, `foreR`, `legL`, `shinL`, `legR`, `shinR`).
Точное имя роли всегда перевешивает поиск по синонимам.

### Оси вращения: `ModelSpaceAnimation`

`SkinAnimator` крутит кости вокруг их **собственных** осей и считает, что
«взмах вперёд-назад» — это поворот вокруг локального X. У большинства ригов так
и есть, но у Source-ригов (Dota) взмах идёт вокруг локального Z: та же рука при
повороте вокруг X уезжает вбок, а не вперёд.

Для таких моделей в скине ставят `ModelSpaceAnimation = true`. Тогда поворот
считается в **системе модели** (`Inv(родитель) · Euler · родитель · поза покоя`),
и X снова означает «вперёд-назад», как бы кость ни была повёрнута внутри модели.
Смещения костей вверх (`SetPos`) там же переводятся в родительскую систему, с
поправкой на собственный масштаб модели.

**Если позже захочешь настоящие анимации:** создай Animator Controller на
модели и назначь его — `SkinAnimator` сам отойдёт в сторону (`DrivenByAnimator`)
и не будет трогать кости. Тогда анимации должны быть в геймплее, а не в
`Animator` префаба.

| Хром | 8 очков |
| Неон | 200 монет |
| Золото | 700 монет |

Импортированные FBX — 2 штуки:

| Скин | Файл | Скелет | Условие |
|---|---|---|---|
| Маг крыльев | `lowpolymage.fbx` | нет (3 меша, крылья) | доступен сразу |

### Замечания по этим двум

- **Тёмная Ива** — 5 сабмешей (`armor`, `head`, `wings`, `chakram`, `base`),
  у каждой своя пара текстур. В FBX диск назван `chakram`, а текстуры пришли
  как `offhand` — поэтому в коде ключ `"chakram"` смотрит на файлы
  `dark_willow_offhand_*`. На бегу подол/хвост опускается на ~10 см ниже
  ступней: это поза без IK для стоп, косметика, не баг.
- **Маг крыльев** — цвет своего материала сохраняет (`TintImported = false`),
  а `ModelScale = 0.8`: размах крыльев в FBX 2,85 м при росте 1,9, в таком
  виде крылья проходят сквозь платформы. Правится одним числом.

#### Оружие в руках: `BonePoses`

В моделях Dota оружие **в bind-pose лежит у ног** — в руку его ставит только
анимация. Раз анимация процедурная, клипов нет, и крюк остался бы валяться на
земле. Скин задаёт рабочие позы костей оружия (`skin.BonePoses`), снятые с
клипа покоя/бега FBX (там они одинаковые):

```csharp
skin.BonePoses.Add(Pose("weapon_rt_1", 0.18f, 0.07f, 0.02f, 4.79f, 83.24f, 93.53f));
skin.BonePoses.Add(Pose("weapon_lf_2", -0.01f, 0.14f, 0.07f, 13.88f, 277.42f, 264.73f));
```

Позы выставляются **до** подгонки модели, иначе крюк на земле раздувает
габариты, по которым считается масштаб. Поэтому же `SkinApplier` теперь меряет
габариты по текущей позе (`SkinnedMeshRenderer.BakeMesh`), а не по bind-pose
мешу.

#### Дубли мешей: `HiddenParts`

В некоторых моделях (например, из Dota) крюк лежит дважды — оба дубля висят на
одной кости и мерцают друг в друге. Лишний гасится по имени узла:

```csharp
skin.HiddenParts.Add("weapon.vmdl_c.weapon_model");
```

## Горячие клавиши и кнопки для тестов

`Assets/Scripts/Dev/DevCheats.cs` включается сам, ничего на сцену вешать не
надо. Весь класс закрыт `#if UNITY_EDITOR || DEVELOPMENT_BUILD`, поэтому в
обычный билд он **не попадает** — ни кода, ни метода автосоздания.

В левом верхнем углу появляется панель `DEV CHEATS` со счётчиком нажатий и
семью кнопками. Кнопки работают мышью, клавиши — только когда окно игры
в фокусе.

| Клавиша | Кнопка | Действие |
|---|---|---|
| `F1` | +100 монет | выдать монеты |
| `F2` | +1000 монет | выдать монеты |
| `F3` | +100 очков | выдать очки |
| `F5` | След. скин | следующий скин по кругу, принудительно открывая |
| `F6` | Тёмная Ива | надеть `dark_willow` |
| `F7` | Классик | надеть `classic` |

Цены в `SkinCatalog` читы не меняют — 900 монет остаются настоящей ценой.
`F5`/`F6` просто помечают скин открытым в обход оплаты, чтобы не ждать
рекорда, и сразу переодевают модель (иначе она меняется только при спавне).

Панель лежит на отдельном канвасе с `sortingOrder = short.MaxValue`.
Через `OnGUI` её делать нельзя: IMGUI рисуется **под** Screen Space Overlay
канвасами, и непрозрачная панель меню её закрашивает.

## Экономика

- **Монеты**: +25 за каждый новый чекпоинт (впервые), +100 за каждые 100 м
  рекорда, +1 за монетку в уровне (каждая 7-я платформа).
- **Очки**: +1 за каждые 10 м нового рекорда.
