# Подключение Yandex Games SDK

Добавлен фреймворк для работы с Yandex Games SDK (WebGL).

## Файлы

- `Assets/Plugins/WebGL/YandexGames.jslib` — JS-bridge с функциями `YG_*` (базовые: init/ready/fullscreen/rewarded, данные игрока, лидерборд, платежи, метрика).
- `Assets/Scripts/Yandex/*.cs` — C# обёртки (`YandexSdk`, `YandexGames`, `YandexAds`, `YandexPayments`, `YandexCloudSave`, `YandexLeaderboard`, `YandexAnalytics`, `YandexConfig`).
- `Assets/Scripts/UI/LeaderboardUI.cs` — простая панель лидерборда (ТОП по рекорду высоты).
- `Assets/Editor/YandexGamesBuildHook.cs` — пост-обработка сборки WebGL: добавляет `<script src="https://yandex.ru/games/sdk/v2"></script>` в `index.html`, растягивает холст на всю область площадки и снимает выделение/контекстное меню.

## Конфигурация

Редактируйте `Assets/Scripts/Yandex/YandexConfig.cs`:
- `LeaderboardBestHeight` — техническое имя лидерборда в консоли Яндекса (по умолчанию `best_height`)
- `ProductSeasonPass` — ID товара в консоли для покупки премиум батл-пасса (по умолчанию `season_pass`)
- `MetricaCounterId` — ID счётчика Яндекс.Метрики (0 отключает)
- `InterstitialCooldown` — минимальный интервал межстраничной рекламы (сек)

## Что подключено

- **Инициализация**: `YandexGames` создаётся автоматически (`[RuntimeInitializeOnLoadMethod]`) на WebGL и вызывает `YaGames.init()`. После готовности меню вызывает `LoadingAPI.ready()`.
- **Облачные сохранения**: автоматическая загрузка/слияние PlayerPrefs по ключевому набору (прогресс, скины, премиум пасса, метрики, достижения). Сохранение при ключевых событиях.
- **Лидерборды**: отправка рекорда высоты (`best_height`) при улучшении рекорда и при завершении отрезка забега. Панель `LeaderboardUI` с кнопкой в главном меню.
- **Покупки**: покупка сезонного пропуска (`season_pass`) из панели Батл-пасса. При наличии товара премиум активируется.
- **Реклама**: автоматический показ fullscreen interstitial (с кулдауном) в главном меню. Кнопка "Реклама +100 монет" в главном меню (rewarded) + по завершению просмотра выдаёт награду.
- **Аналитика**: отправка целей (`sdk_ready`, `run_ended`, `interstitial`, `premium_granted`, `premium_revoked`) через `ym()` при наличии счётчика.

## Требования

1. **Модуль WebGL Build Support** должен быть установлен в Unity Hub (текущий редактор 6000.0.32f1 показывает `windowsstandalonesupport` только). Без него нельзя собрать WebGL.
2. Игра должна быть размещена на платформе Яндекс Игры (или иметь доступ к `YaGames`). В редакторе WebGL-мост не активен — код деградирует до локальной работы.
3. В консоли Яндекса создать лидерборд с техническим именем `best_height` и товар `season_pass` (при использовании покупки).

## Сборка WebGL

1. Установите WebGL Build Support для версии 6000.0.32f1 (Unity Hub → Installs → версия → **Add modules** → WebGL Build Support). Сейчас этого модуля нет, и сборка невозможна.
2. Файл → Build Settings → Platform WebGL → Switch Platform.
3. Project Settings → Player → WebGL → Template: Default (файл сборки пропатчится пост-хуком).
4. Build. После сборки `index.html` будет содержать скрипт `https://yandex.ru/games/sdk/v2`.

Или одной командой — сборка, проверки и архив сразу:

```
Unity.exe -batchmode -quit -nographics -projectPath "<путь к проекту>" -executeMethod WebGLShip.Run -logFile "%TEMP%\ship.log"
```

`Assets/Editor/WebGLShip.cs` применяет релизные настройки, собирает включённые сцены в `Build/WebGL`, проверяет готовую папку и кладёт рядом `Build/ParkourInParadise.zip`. Проверки перед упаковкой — это те требования, нарушение которых видно только на модерации:

- `index.html` есть и лежит в корне (1.22), в нём стоит скрипт SDK (1.1);
- в именах файлов и папок нет пробелов и не-латиницы (1.22);
- распакованное содержимое меньше 100 МБ (1.21);
- `includeBaseDirectory: false` — внутри архива нет лишней папки-обёртки, `index.html` действительно в корне.

Код выхода — ноль, если архив готов к загрузке.

## Выкладка в консоли разработчика

Сборка загружается целиком, игры на своём сервере держать не нужно: если у игры нет серверной логики, площадка сама раздаёт архив (свой хостинг — только через `iframe` и по согласованию с поддержкой).

1. Завести **аккаунт разработчика**: https://games.yandex.ru/console → создать игру → заполнить **Черновик**.
2. Шаг 1: **Архив** — загрузить `Build/ParkourInParadise.zip`; **Поддерживаемые платформы** — выбрать только **Десктоп** (управление с клавиатуры и мыши, 1.6.1.5 требует жестового управления для мобильных); **Ориентация** — любая.
3. Шаг 2: языки (сейчас игра только на русском — 2.14), возрастной рейтинг, категории, теги, ключевые слова.
4. Шаг 3: включить **Игра использует облачные сохранения** — требование 1.11 при работе с `Player.setData()`. В комментарии разработчика стоит написать про свой JS-мост и про то, что звука в игре нет.
5. Шаг 4: **Название** — «Паркур в рай», **Об игре** и **Как играть** (управление описано словами, 2.2).
6. Шаг 5: иконка 512×512 PNG, обложка 800×470 PNG. Скриншоты из игры не годятся ни на иконку, ни на обложку (5.6).
7. Шаг 6: горизонтальное видео 16:9 до 28 секунд и не меньше двух десктопных скриншотов 16:9 (по длинной стороне от 1280 до 2560 px).
8. В консоли создать **лидерборд** `best_height` (ТОП по рекорду высоты) и товар `season_pass`, если покупка идёт в релиз; счётчик Метрики вписать в `YandexConfig.MetricaCounterId`.
9. Проверить игру из черновика в режиме черновика и с **debug-панелью**, затем «Отправить на модерацию». Модерация обычно занимает 3–5 рабочих дней.

### Название в игре и в карточке

Требование 5.1.3 — название на титульном экране и в материалах черновика должно совпадать, а поле **Название** в консоли не принимает текст сплошными заглавными (8.2.1, полный капс запрещён). Заголовок в главном меню приведён к «Паркур в рай», то есть к тому же виду, в каком название пойдёт в черновик; заглавные больше не расходятся между игрой и карточкой.

## Подготовка к релизу

Релизные настройки держим кодом, а не галочками в окне: настройка, сделанная мышью, нигде не записана и теряется при переносе проекта.

- `Assets/Editor/ReleaseSetup.cs` (`ReleaseSetup.Run`) — имя сборки и разработчик:
  - `productName = ParkourInParadise`, только латиница без пробелов. Файлы Unity называются по `productName`, а требование 1.22 запрещает кириллицу и пробелы в именах файлов и папок архива. Само название игры кириллическое — «Паркур в рай» — и задаётся в карточке консоли и на титульном экране (требование 5.1.3: имя в игре и в материалах должно совпадать).
  - `companyName = Tanks in Greece`, стартовый размер холста 1920x1080.
- `Assets/Editor/SkyboxImport.cs` — ограничивает текстуры пака неба до 1024 по длинной стороне. Без него двенадцать кубов 8192 уезжали в сборку на ~268 МБ (лимит площадки — 100 МБ, требование 1.21) и занимали по четверти гигабайта видеопамяти каждый. После правки сборка — около 42 МБ, небо — 0.02 ГБ вместо 0.28 ГБ.
- `Assets/Editor/ReleaseAudit.cs` (`ReleaseAudit.Run`) — отчёт `ReleaseAuditReport.txt`: что попадёт в сборку, сколько весит (текстуры — по весу в сборке, а не по исходному PNG) и где мусор. Прогонять перед выкладкой.
- `Assets/Editor/WebGLShip.cs` (`WebGLShip.Run`) — сборка WebGL, проверки готовой папки и ZIP-архив для консоли: `Build/WebGL` и `Build/ParkourInParadise.zip`. Подробности ниже.
- `Assets/Editor/ReleaseSetup.cs` — здесь же сжатие сборки: Brotli плюс запасной распаковщик (`decompressionFallback`). Заголовки сервера площадки нам не подконтрольны, а с запасным распаковщиком игра стартует и там, где `Content-Encoding: br` не отдаётся (1.20). Если на слабых телефонах старт окажется долгим — в `ReleaseSetup.Apply` меняется одна строка на `WebGLCompressionFormat.Gzip`.
- `Assets/Editor/YandexGamesBuildHook.cs` — холст на всю область площадки (требование 1.6.2.1), скрытие WebGL-уведомления шаблона (1.6.1.7), запрет выделения и контекстного меню по долгому тапу (1.6.1.8, 1.6.2.7).
- Кнопка «Выход» убрана из главного меню: в браузере `Application.Quit()` ничего не делает, а площадка рекомендует избавляться от кнопок без пользы (п. 6.7). Вместе с ней убран и никому не нужный `GameManager.QuitApp`.
- Из проекта вычищены: `LevelManager.cs.bak`, примерные сцены пака неба (в сборку не входят, но мешают), пустая папка `Assets/Audio`.

### Проверить перед выкладкой

1. **WebGL Build Support** для 6000.0.32f1 установлен; сборка `Build/ParkourInParadise.zip` уже собрана. После правок кода пересобрать.
2. Прогнать `WebGLShip.Run`: он сам проверит вес, имена и `index.html` и остановится с ошибкой, если что-то не так.
3. Открыть `ReleaseAuditReport.txt` (`ReleaseAudit.Run`) и убедиться, что мусор в сборку не попал.
4. Запустить игру из черновика и посмотреть старт: если распаковка на слабом устройстве затягивается, сменить формат сжатия на Gzip.
5. В консоли Яндекса создать лидерборд `best_height` и товар `season_pass`, вписать счётчик Метрики в `YandexConfig.MetricaCounterId`, включить галочку облачных сохранений.
6. Сверить название: в консоли «Паркур в рай», на титульном экране — тоже без полного капса (5.1.3).

### Что учесть отдельно

- Звука в игре нет вовсе, поэтому требование 1.3 (останавливать звук при потере фокуса) выполнять нечего.
- Интерфейс только на русском. Требование 2.14 про автоопределение языка пройдёт лишь для одноязычной игры; язык площадки читается в `YandexGames.Lang`, но тексты не переводятся.
- Из двенадцати скинбоксов игра ставит шесть; остальные лежат в `Resources` и попадают в сборку. На вес это уже не влияет (около 3 МБ каждый), поэтому оставлены как запас.

## Как проверить в редакторе

Все файлы защищены `#if UNITY_WEBGL && !UNITY_EDITOR` в `YandexSdk`. Объект `YandexGames` создаётся только на WebGL. В редакторе интерфейсы будут работать локально. `AllChecks` продолжает работать без изменений.

## Известные ограничения

- Облачное слияние: для числовых ключей берётся максимум (local, cloud) — предотвращает потерю прогресса, но не запрещает "возвращение" монет/XP при десинхронизации (данные записываются на ключевых действиях).
- Задания дня и ежедневная награда хранятся по дню; их синхронизация между устройствами в рамках этого MVP не включена.
- Для покупок используется `signed:false` (клиентская обработка) — по желанию можно переключить на `signed:true` и обработку на сервере.
- Цели Яндекс.Метрики (`YandexAnalytics.Goal`) уходят только при `counterId > 0` в `Assets/Plugins/WebGL/YandexGames.jslib`; сейчас там `0`, то есть цели отключены. Базовую статистику площадка собирает сама. Если нужен номер счётчика — вписать его в `counterId` и пересобрать WebGL.

## Примечание

Подход самодостаточный: используется JS-bridge через jslib, без внешних `.unitypackage` Яндекса.
